# Simulated first-time setups of ActivityBot

## Person 1: Priya, illustrator, non-technical, cheap shared cPanel hosting, Windows laptop

"I want a little bot that posts my daily sketch. The Quickstart is four lines, nice. 'Create a subdomain' - OK, cPanel has that. 'Upload `index.php`, `.htaccess`, `.env.example`' - I can't see `.htaccess` in my file explorer. I had to turn on hidden files. Then 'Rename `.env.example` to `.env`', but the Set Up section says rename *first*, fill it in, and then upload `.env`. Which one do I do? Do I edit it on the server or locally?

I open the file. 'Generate locally by opening `tools/rsa_key_generator.html`'. I only have three files from the Quickstart. I download the whole repo and find it. It makes two long blocks, and now I'm told 'Newlines must be replaced with "\n"'. How? By hand? I did it in Notepad with find and replace and I'm not sure I got it right. Then 'PASSWORD' needs `password_hash(...)`, which is PHP, and I don't have PHP on my laptop. `php tools/generate_password.php` - what is `php`? I'm stuck for an hour and nearly quit.

My host's PHP selector tops out at 8.3. The README says 'PHP 8.5 (We live in the future now.)' and nothing about what happens on 8.3. Does it work? Will it break? I leave the PHP version alone and hope. I visit `/.well-known/webfinger` and get an error page (or maybe a blank page). The README says it should show JSON, but not what to do if it doesn't. Is it the PHP version, `.htaccess` being ignored, or my `.env`? No idea. I stop."

## Person 2: Sam, sysadmin, Ubuntu VPS, wants nginx

"Fine, I'll use the nginx page. 'Requires `php8.5-fpm`' - Ubuntu's repos don't ship 8.5 and it doesn't say which third-party repo. I run `sudo apt-get install php php-curl` as instructed and it pulls in Apache, which grabs port 80 so nginx won't start. Nothing mentioned installing nginx at all, or where the config file goes, or enabling the site and reloading. I sort that out.

I paste the config. It listens on port 80 only, while the main README says an HTTPS certificate is required and the test URL is `https://...`. I run certbot on my own. The deny rule `location ~ ^/(.env|data)` has unescaped dots, so it also matches paths like `/database`, and `deny all;` followed by `return 404;` is redundant and confusing. The comment 'I don't THINK these are needed but computers are oh so very confusing' doesn't inspire confidence about the commented-out lines.

I create `test.php` as described. Visiting it shows 'Path is...' plus a PHP warning about an undefined key, so I can't tell whether that's success. It also doesn't say to delete `test.php` after. Then step 7 says 'Check your `data/logs/` directory' - but who creates `data/`? PHP-FPM runs as www-data and my web root is owned by me. The nginx page says nothing about permissions (the Caddy page does). I chown it by trial and error."

## Person 3: Dana, homelab enthusiast, Docker and Traefik on a NAS

"README_docker.md calls itself 'Rough Docker Instructions', and it is. The compose block is a fragment: no `services:` key, no `ports:` for people not using Traefik. How would I reach it without Traefik? The volume `/path/to/your/docker/stuff/activity-bot/:/var/www/html/public` - presumably that's where I put `index.php`, `.htaccess`, `.env`, but it doesn't say so. The second volume points to `activity-bot.conf`, which I have to realise is the nginx config in the next section; no one tells me to save it under that name. The `environment:` key is left with only a comment under it, which may be an invalid empty mapping in compose.

Copy-paste leftovers: '# Internal port for postiz' (what's postiz?), `your.host.com` in the Traefik rule but `you.host.com` in `server_name`. The entrypoint `web-secure` is specific to someone's setup. The nginx config here uses `fastcgi_pass 127.0.0.1:9000` while the other page uses a socket. Does my conf in `conf.d` replace the image's default server or clash with it on port 8080? No explanation. I also can't confirm `serversideup/php:8.5-fpm-nginx-alpine` is a tag that exists; the README doesn't link to it. I get it going after reading the image's docs myself."

## Person 4: Jo, Raspberry Pi at home, Caddy, residential internet

"The intro says it runs on a Raspberry Pi, but I find no Pi-specific setup. I take the Caddy page. It doesn't say how to install Caddy, where the Caddyfile lives, or how to reload. It also doesn't mention that to get a certificate I need DNS pointing to my home IP and ports 80/443 forwarded; the main README says only 'HTTPS certificate (Let's Encrypt is fine.)'. Raspberry Pi OS also doesn't have `php8.5-fpm` in its default repos, and `apt-get install php` there pulls in Apache again.

Reading the Caddyfile: it blocks `/.env` and `/php_errors.log` only. The nginx pages also block `data`, which holds the logs. Caddy leaves `data/` open? I add a block myself, but a less careful person wouldn't. `php_errors.log` appears nowhere else in the docs. Then 'You may have to adjust the permissions... as Caddy and PHP often run as different users' - which users, what commands? I use `test.php` and see a warning about an undefined array key; is it working? I assume yes."

## Person 5: Lena, data scientist, strong Python, new to PHP and the Fediverse

"I'll use Apache on a small VPS, following the main README; it says 'The default set up assumes Apache or similar' but never mentions enabling `mod_rewrite` or `AllowOverride All`, or how to run PHP (mod_php or FPM). My `.htaccess` is ignored at first and `.env` is publicly readable, with the private key inside. The README never warns me about that.

I do the setup, but step 5, 'search for your user', needs a Fediverse account. I don't have one, and there's no pointer on how to get one. `/.well-known/webfinger` with no `?resource=` returns an error for me instead of 'a JSON file with your user's details'. I try with `?resource=acct:name@domain` and it works.

I move on to the API. 'Requirements' says I should have Requests installed, but not how, and the Debugging section needs `requests_toolbelt`, which isn't mentioned. The examples say `"password": "your-password-here"` - is that the hash I put in `.env` or the plain password? The text says it's 'encrypted when you send it and never stored'. The location example has `"longitude": 40.77563, "latitude": -73.97474` and I recognise those as swapped (that's roughly New York, latitude first). For Delete and Edit I need the `guid`: 'You will need the ID of your post' - from where? 'See `$allowed_elements`' - in which file? I can't find unfollow, block, unblock or the quote-post option in the API section, though the Features list claims them. The image example uses the alt text as the file's 'name' in a tuple, which is not explained, and I'd never guess it. I spend a while reading `index.php` to fill these gaps."

# PROBLEMS

1. The Quickstart and Set Up disagree on order. Quickstart says "Upload `index.php`, `.htaccess`, `.env.example` to your subdomain" then "Rename `.env.example` to `.env`", while Set Up says rename and fill in `.env` first and then "Upload `index.php`, `.htaccess`, and `.env`". It is unclear whether to edit locally or on the server.
2. The Quickstart doesn't say to upload to the root directory; only Set Up says "It will not work in a subdirectory." The Quickstart also doesn't mention `tools/rsa_key_generator.html`, which is not among the three files it tells you to upload.
3. The Set Up list numbers its steps "0." then repeats "1." for every other step. In raw text it is hard to tell which step is which, and the references to step order (for example the log check) are ambiguous.
4. The PHP requirement "PHP 8.5 (We live in the future now.)" gives no way to check your version, no advice for shared hosts that only offer older PHP, and no statement of what fails on 8.3 or 8.4. It sits awkwardly with "It will run on shared hosts, a Raspberry Pi, or any modern web server."
5. "This should include the following extensions by default" is vague (should or does?). The linked pages are a release-announcement anchor and the manual for OpenSSL, not installation or verification instructions.
6. The `.env.example` instruction "Generate locally by opening `tools/rsa_key_generator.html` on your computer. Newlines must be replaced with "\n"" says nothing about how to use the page, what to copy, whether it works offline and is safe, or how to convert the newlines. The placeholder shows `...` rather than a realistic key shape.
7. Password generation depends on PHP being installed locally ("`php tools/generate_password.php 'Y0ur_p4s5w0rd'`" or `password_hash(...)`) with no alternative for non-PHP users. It also doesn't mention shell-history exposure, whether the hash's `$` characters are safe inside the quotes in `.env`, or that the API's "your-password-here" is the plain password and not the hash.
8. "The password is encrypted when you send it and never stored on your server" is misleading. The password is only protected by HTTPS in transit, and a hash of it is stored in `.env`.
9. The README never warns that `.env` (containing the private key) lives in the web root and depends on `.htaccess` being honoured. Apache setup needs `mod_rewrite`, `AllowOverride` and a PHP handler, none of which is mentioned, though the intro promises it runs on a Raspberry Pi or any modern web server and only nginx, Docker and Caddy pages exist.
10. The Quickstart and Set Up say "Create a subdomain" without explaining DNS, hosting panels, free subdomain options (the FAQ says "you should create free subdomains") or what to do if the main domain is hosted elsewhere. Dotfiles (`.htaccess`, `.env`) are also easily hidden by file managers and operating systems, and this isn't mentioned.
11. "If you prefer, you can edit `index.php` and place the details in there" gives no location, variable names or format.
12. `.env.example` leaves example values in "Optional Fields" that would be published as-is (display name, summary linking to the project, `PROFILE_VALUE_3` mentioning another person's account, and `PROFILE_VALUE_4` pointing at `https://example.com/tag/ActivityBot`). It doesn't say whether to blank, replace or keep them. Comment style is also inconsistent: "`#	This is the joined date of your bot.`" lacks the `;` used elsewhere, and `MAX_LOGS=2048` is unquoted while `PAGE_SIZE="1000"` is quoted.
13. The webfinger check, "Visit `https://test.example.com/.well-known/webfinger` and check that it shows a JSON file with your user's details", omits the `?resource=acct:` query a webfinger endpoint normally needs. There is no troubleshooting for 404, 500, blank pages or wrong PHP version.
14. Following your bot ("Follow your user") assumes the reader already has a Fediverse account. There is no help for those who don't, no mention of whether the bot auto-accepts, and no statement of what a correct entry in `data/logs/` looks like.
15. "Check your `data/logs/` directory" never states that `data/` is created on first run, by which user, or where it lives. Write permissions are only discussed in README_caddy.md ("You may have to adjust the permissions...") and not in the main README or README_nginx.md.
16. Step 8 says "upload an avatar and banner image" and "Edit `.env` to include the image locations", but `.env.example` only says "relative URl without leading slash" without saying relative to what. Nothing tells the reader to run the "Update Account" call afterwards, which the API section says is needed ("you will need to tell your followers").
17. The API section only gives Python examples, assumes the Requests library ("have installed the popular Python Requests library") with no install command, and the Debugging snippet needs `requests_toolbelt`, which isn't listed. There are no curl or non-Python examples, no description of responses or error codes, and the examples don't print or check `r`.
18. "You can send HTML. See `$allowed_elements` to see which ones are supported." refers to a variable without naming the file or where to look.
19. The Edit and Delete examples say "You will need the ID of your post" but not where to find the `guid`.
20. Features list unfollow, block, unblock, attach video and audio, and "Allow quote posts", but the API section has no documented request for unfollow, block, unblock, or quote-post permission. Video and audio are covered only by "You can also post audio and video in the same way."
21. The image example, `files = [("1",("This is the alt text", open("red.png", "rb")))]`, uses the filename slot as alt text without saying so, and gives no size, format or limit information for media.
22. The location example has latitude and longitude swapped: `"longitude": 40.77563, "latitude": -73.97474`. Those values are the New York latitude and longitude in the opposite order.
23. The Migrate Accounts text is confusing. Moving away says "Once your new acount is set up, go to your new account and follow its procedure for moving followers to it. Then you will need to send a Move request", leaving the order unclear. `NEW_NAME` takes a full URL (`"https://new.example/users/username"`) but the API example sends `"user": "@new@example.com"` in handle format. There is also a typo ("acount").
24. The README mentions "Bridge to BlueSky with your domain name via Bridgy Fed" as a feature and `DID` in `.env`, but gives no bridging steps.
25. README_nginx.md and README_caddy.md say "Requires `php8.5-fpm`" and run `sudo apt-get install php php-curl` then `php8.5-fpm`. `php8.5-fpm` is not in the default distribution repositories and no third-party repo is named. The `php` meta-package can also pull in Apache, which clashes with nginx or Caddy on port 80. The pages also don't cover installing nginx or Caddy, where the config goes, enabling the site, or reloading.
26. The nginx example only has `listen 80;`, yet its test URL is `https://test.example.com/test.php` and the main README requires HTTPS. No certificate steps are given.
27. The nginx block `location ~ ^/(.env|data)` has unescaped dots and prefix matching (it also matches `/database`), and combines `deny all;` with `return 404;`. The configuration also contains the comment "I don't THINK these are needed but computers are oh so very confusing", which leaves the reader unsure about the commented lines. The code fence is labelled `bash` rather than nginx.
28. The Caddy config only blocks `/.env` and `/php_errors.log`, not `data/`, which the nginx configurations do block. `php_errors.log` is not mentioned anywhere else in the docs. The Caddy page also doesn't say where the Caddyfile lives or how to reload it.
29. The `test.php` check in both nginx and Caddy pages ("Then access it at `https://test.example.com/test.php`") doesn't say where to put the file, prints an undefined-key warning when `?path=` isn't supplied, doesn't define what success looks like, and doesn't say to delete the file afterwards.
30. README_docker.md is described as "Rough Docker Instructions" and is a fragment. There is no `services:` key and no `ports:` for non-Traefik users. It doesn't say what goes in `/path/to/your/docker/stuff/activity-bot/` or that the second volume `activity-bot.conf` is the nginx config from the next section. The `environment:` key contains only a comment.
31. The Docker page has copy-paste leftovers and mismatches: "# Internal port for postiz", `Host(`your.host.com`)` versus `server_name you.host.com;`, a site-specific `web-secure` entrypoint, `fastcgi_pass 127.0.0.1:9000` versus the socket used elsewhere. It isn't clear whether the mounted file replaces or collides with the image's default server config, and the image tag `serversideup/php:8.5-fpm-nginx-alpine` is not linked or verified.
32. Heading structure is off: "Set Up" and "Other Servers" are level-3 headings under "Minimum Requirements", and a second heading named "Requirements" appears under "Using the API". The text also has typos such as "Lenny" (probably Lemmy) in the intro, "URl" repeatedly, and "acount".
33. The FAQ says "you can adjust this" for log retention without naming `MAX_LOGS`. The `.env.example` log comment mentions exhausting "file limits" while the README only discusses disk space.
34. The repository contains `AGENTS.md` and `CONTRIBUTING.md`, but neither is referenced from the README. The "What is your AI policy?" section says "you must attest that you are a human and wrote the code yourself" without saying where or how to attest, and an `AGENTS.md` file next to a no-LLM policy may confuse readers.
